## Fix Plan for OBSINTA-1343

### Version
Plan v1 | Iteration 1 (audit-approved)

### Root Cause
The `e2e-aws-ovn-conformance-serial` periodic test creates a HyperShift hosted cluster using the `hypershift-aws-conformance` workflow, which invokes the `hypershift-aws-create` chain. This chain defaults `HYPERSHIFT_INFRA_AVAILABILITY_POLICY` to `SingleReplica` (line 52 of `ci-operator/step-registry/hypershift/aws/create/hypershift-aws-create-chain.yaml`). With SingleReplica infra topology, infrastructure services including the ingress controller (router-default deployment in `openshift-ingress` namespace) run only one replica. During serial conformance tests (`openshift/conformance/serial` suite), certain tests apply `NoExecute` taints to nodes. When such a taint is applied to the node hosting the sole ingress controller pod, the pod is evicted with no replacement available, causing ingress to become unavailable and downstream tests to fail.

### Approach
Set `HYPERSHIFT_INFRA_AVAILABILITY_POLICY: HighlyAvailable` in the `env` section of the `e2e-aws-ovn-conformance-serial` test definition across all release version periodics configuration files (4.14 through 5.0). This ensures all infrastructure services (ingress controller, DNS, image registry proxy, etc.) have multiple replicas. With multiple replicas, even if one pod is evicted due to a NoExecute taint, the remaining replicas continue serving traffic.

This is a configuration-only change to CI test definitions. It does not modify the HyperShift operator, the step registry, or any production code. The change is purely additive (adding one env var to each test definition).

**Precedent**: The `HYPERSHIFT_INFRA_AVAILABILITY_POLICY: HighlyAvailable` env var override is already used by MCE conformance tests in `*__periodics-mce.yaml` files (e.g., `openshift-hypershift-release-4.21__periodics-mce.yaml` line 325). While the MCE tests use a different workflow (`hypershift-mce-power-conformance`), the env var mechanism is identical — it overrides the same chain default in `hypershift-aws-create-chain.yaml`.

### Alternatives Considered
| # | Approach | Pros | Cons | Why Not |
|---|----------|------|------|---------|
| 1 | Add NoExecute tolerations to the ingress controller after cluster creation | Directly addresses the eviction issue | Requires a new step in the workflow chain; modifies shared infrastructure; doesn't address other SingleReplica issues | Too complex; changes shared workflows affecting all tests |
| 2 | Change the default in the chain from SingleReplica to HighlyAvailable | Fixes all tests at once | Would change behavior for ALL tests using this chain, not just conformance-serial; may increase resource usage significantly for unrelated tests | Too broad; violates principle of least change |
| 3 | Skip taint-related tests in the serial conformance suite | Avoids the eviction entirely | Tests exist for a reason; skipping them reduces coverage | Would mask rather than fix the underlying vulnerability |

### Implementation Notes
1. **Key ordering**: Insert `HYPERSHIFT_INFRA_AVAILABILITY_POLICY: HighlyAvailable` BEFORE `TEST_SUITE` in the env block to maintain alphabetical ordering (H < T). The `determinize-ci-operator` tool (run via `make update`) enforces alphabetical ordering, but inserting in order keeps diffs clean.
2. **Mandatory post-edit steps**: Run `make update` after all config edits. This regenerates Prow job configs in `ci-operator/jobs/` and updates `zz_generated_metadata`. Both the edited config files AND the regenerated job files MUST be committed together.
3. **Validation**: Run `make checkconfig` after `make update` to validate the generated Prow configuration.
4. **Config-brancher boundary**: These `__periodics.yaml` files are manually maintained and NOT subject to `config-brancher` overwrite, so the fix will persist across releases.

- [ ] Database migration? **No**

- [ ] Error handling / logging change? **No**

The additional resource consumption is acceptable for conformance testing reliability and is consistent with the existing MCE conformance test configuration.
